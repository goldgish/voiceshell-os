# 语音播报评测标准 + 评判记录与改进清单

> 本文档三件事：① 本项目可落地的评测标准（持续修订）；② 各轮评判结论；③ 修改任务清单（供执行 agent 施工）。
> 设计参考：EVA-Bench（准确性/体验双轴）、VoiceAgentBench、NVIDIA 语音 Agent 实践（首响 600–1500ms）。
> 本项目特点：**播报即产品**——用户不看屏幕，speak 是唯一主反馈通道。

---

## 一、评测标准（当前版本 v2）

### A 层：硬指标（runner 自动判，门槛制，任一 FAIL 即整体 FAIL）

| # | 指标 | 阈值 | 实现状态 |
|---|---|---|---|
| A1 | 回合完成度 | `finish == completed`；max-tokens/异常 = FAIL | ✅ 已实现 |
| A2 | 首声延迟 TTFS | ≤3s 优 / ≤6s WARN / >6s FAIL | ✅ 已实现 |
| A3 | 播报条数区间 | 按 case `expect.speaks` | ✅ 已有 |
| A4 | 必含/禁含概念 | 正则，任一播报命中 | ✅ 已有 |
| A5 | 预告措辞 | 全条目检查；句中含"同意/确认/要不要/可以吗"时豁免 | ✅ 已实现 |
| A6 | 单条长度（**v2 拆分型**） | 见下方分型规则 | ⚠️ 需改造（v1 已实现，分型未做） |
| A7 | 静默缺口 | 任何 >95s 完全静默段 = FAIL | ✅ 已有 |
| A8 | 语言一致性 | speak 必须含中文；final_text >20 字且零中文 = WARN | ✅ 已实现 |
| A9 | **连播间隔**（v2 新增） | 相邻 speak 间隔 <3s 且前一条 >15 字 = WARN（应合并；TTS 顶断风险，见 M3） | ❌ 待实现 |

**A6 分型规则（v2 修订）**：播报分两类，阈值不同——
- **汇报型**（进度、状态、开场、收尾）：≤30 字铁律，收尾 ≤60 字；超 1.5 倍 FAIL
- **交付型**（纯问答的答案播报，内容本身就是交付物，如 c01/c10）：单条 ≤80 字；鼓励一条播完，不拆条
- 分类方式：case 的 `expect.speaks_max ≤3` 且无工具的纯问答案（c01/c10 型）按交付型；其余按汇报型。runner 可按 case 打标

### B 层：评审维度（judge 读 trace 打 1–5 分，不进门槛）

| 维度 | 5 分锚定 | 1 分锚定 |
|---|---|---|
| B1 时机感 | 开场/里程碑/阶段切换/收尾全命中且无滥播 | 该播不播（**含"想到了却自我说服不播"**）、不该播乱播 |
| B2 措辞品质 | 口语、概念级、带数字、不复述屏幕 | 念路径/念工具名/书面腔 |
| B3 诚实信任 | 不伪装成功、不空承诺、失败 decision-first、不可逆先问 | 报假功、擅自执行不可逆操作 |
| B4 陪伴节奏 | 长任务无声 ≤35s、挣扎时给状态、不刷屏 | 死寂或连珠炮 |
| B5 任务达成 | 产物真实存在且符合要求（对 workspace 验货） | 无产物或产物不符 |

用户给的是长线任务："自己迭代，发现问题先说一声再直接改，再用测试机跑一遍验证。"

   已修：放宽到自然说法（没打开/看不了/不存在/解析不了/没能），并在 case notes 里写明原因。

4. **A9 误伤开场**：c05 的 1.8s 开场 + 4.2s 失败结论（间隔 2.4s）被判"应合并"，

### 第五轮 20260913（同日晚续）：抓到最严重的一类问题——提示词漂移

**发现**：播报纪律存在两份、靠人工同步。`app/voice_prefix.py`（跑器用，归一化 995 字）
比插件 `PROMPT_TEXT`（生产用，635 字）多出一整套规则：

| 生产缺的规则 | 影响 |
|---|---|
| 时间锚定兜底：连续干活超 20 秒没出声就播一句 | **正是 c04 那个 50 秒静默带的直接病因**——线上压根没这条规则，只有跑器有 |
| 心跳说明（连续 35 秒会提醒你） | 插件刚补的心跳，agent 却不知道有这回事 |
| 挣扎也要出声（连续返工/工具失败后先报状态） | P6 从未生效 |
| 播报句内禁用"我再/我还要/接下来我" | 规则 5 的核心禁例，线上没有 → c05 那句"你把网址发我我再看"就是这么来的 |
| 一条播完不拆条 / 不可只写进文字回复 / 不因任务简单省略开场 | 第二、三轮的修复，全部没进生产 |

**性质**：不是模型行为问题，而是"测试量的规则不是线上跑的规则"——本项目反复出现的假绿。
旧架构下 `voice_prefix.py` 确实是唯一来源；架构成"app → 秘书 → 工作会话"之后，
真正生效的是插件的 host 级 `systemPrompt` 注入，而那份是手抄的旧版本。

**修复**：把插件 `PROMPT_TEXT` 补齐到与 `voice_prefix.py` 同义（仅工具名写法不同：
`mcp__voice__speak` vs `speak`），并新增 `_check_prompt_drift.py` 做**归一化一致性检查**
（统一工具名、去掉空白后逐字符比对，漂移即退出码 1）。现为 `identical=True ratio=1.0000`。

**新增**：`_selftest_all.py` 一键自测（judge 解析 / TTS 连播 / 提示词漂移），3/3 通过、3 秒跑完，
不必等 5 分钟全量评测。**需重启 host 让补齐后的提示词生效。**
